🔧 Core Components

📨 Apache Kafka

Streaming message broker connecting payment system to ML pipeline:

  • transactions — raw payments in
  • fraud-alerts — decisions out
  • Scales to 100K+ msgs/sec
  • Replay capability
  • Durable storage

👂 Transaction Consumer

Spring @KafkaListener consuming transaction stream:

  • Listens on "transactions" topic
  • Deserializes JSON to Transaction
  • Batching & retries configured
  • Non-blocking async processing
  • Error handling & DLQ

🎯 Feature Engineering

Java domain layer extracts ML-ready features:

  • Temporal: hour, day, overnight
  • Categorical: merchant/geo risk
  • Velocity: 1h/24h/30d counts
  • Derived: ratios, normalization
  • Metadata preservation

🤖 ML Scoring

Two-mode scoring: ONNX fast path or REST fallback:

  • ONNX (Primary): 0.18ms per prediction
  • REST (Fallback): HTTP to Python service
  • Auto-switches on ONNX unavailable
  • Returns probability + risk level
  • Feature importances

🚨 Alert Service

Determines fraud decisions and publishes alerts:

  • HIGH risk (prob > 0.85) → BLOCK
  • MEDIUM (0.4-0.85) → REVIEW
  • LOW (< 0.4) → ALLOW
  • Publishes to fraud-alerts topic
  • Includes full decision context

🌐 Downstream Systems

Alert consumers take action on fraud decisions:

  • CRM: Flag customer account
  • Risk Ops: Manual review queue
  • Account Freeze: Block transactions
  • Compliance: Audit trail
  • Analytics: Model monitoring

⏲️ Request-to-Alert Timeline

0ms: Payment System

Card transaction occurs. Payment gateway publishes to Kafka "transactions" topic.

1-5ms: Kafka Receive

Transaction message enters Kafka broker, replicated across cluster for durability.

5-10ms: Consumer Polls

Spring @KafkaListener polls topic, receives batch of transactions, deserializes JSON.

10-20ms: Feature Engineering

FeatureEngineer extracts ~12 ML features from transaction. Queries merchant/geo tables, velocity cache.

20-30ms: ML Scoring (ONNX Fast Path)

Features passed to ONNX Runtime in-JVM. RandomForest predicts fraud probability in <1ms.

30-35ms: Alert Decision

FraudAlertService receives prediction, determines action (BLOCK/REVIEW/ALLOW), creates alert object.

35-40ms: Publish Alert

Alert serialized to JSON, published to Kafka "fraud-alerts" topic, replicated for durability.

40-100ms: Downstream Action

CRM, Risk Ops, Account Freeze consumers receive alert, take action. Total latency: 40-100ms.

🎯 Scoring Modes: Fast vs. Flexible

⚡ ONNX In-JVM (Fast Path)

Primary scoring method when ONNX file available:

  • Sub-millisecond latency
  • No network call
  • No external dependencies
  • Bundled in JAR
  • Deterministic, no failures

🔄 REST Fallback (Flexible)

Fallback when ONNX unavailable or Python service needed:

  • HTTP to Python ML service
  • More model flexibility
  • Can update without restart
  • May have network latency
  • Circuit breaker pattern

🐳 Docker Compose Stack

🐘 Zookeeper

Kafka coordination & leader election. Manages broker cluster state.

📨 Kafka Broker

Message broker. Handles transactions & fraud-alerts topics with persistence.

🐍 Python ML Service

FastAPI server on port 8000. Serves fraud predictions if ONNX unavailable.

☕ Java Pipeline

Spring Boot on port 8084. Consumes transactions, scores, publishes alerts.

📊 Kafka UI

Visual browser on port 9090. Monitor topics, messages, consumer groups.

💾 Persistent Volumes

Kafka data & Zookeeper state persist across restarts. No data loss on reboot.

Score (ONNX fast path or REST fallback) double fraudProb = fraudScoringService.score(features); // 3. Determine action FraudDecision decision = fraudProb > 0.85 ? Publish alert FraudAlert alert = new FraudAlert( txn.transactionId(), fraudProb, decision, features ); fraudAlertPublisher.publish(alert); } catch (Exception e) { log.error("Pipeline error for txn: {}", txn.transactionId(), e); // Publish to DLQ for manual review deadLetterQueue.push(txn); } }
