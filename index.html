The Basics

What is Hermes?

🧠

A Fine-Tuned LLM

Hermes is built on top of powerful base models (LLaMA, Mistral) and fine-tuned by Nous Research to excel at real-world tasks.

🤝

A Conversation Partner

It understands natural language, follows complex instructions, and maintains context across a long conversation.

🔧

A Tool-Calling Agent

Hermes can decide when to call external tools — APIs, databases, code runners — and chain them together.

🗂️

A Structured Output Engine

Ask for JSON, XML, or any schema and it delivers — no regex hacks needed.

Real Use Case

Meet SwiftStock — A Warehouse Supplier

200 retail clients · 5 warehouses · 50,000+ SKUs · 500+ orders/day
Every single problem below is handled manually today.

📥

Order Chaos

Orders arrive via email, WhatsApp, phone, and web portal. Each one needs manual data entry into the ERP — 2 hrs/day just typing orders in.

📦

Blind Inventory

Staff only discover stockouts after a customer orders. No automated reorder triggers — restocking is always reactive, never proactive.

🧾

Invoice Pile-up

100+ supplier invoices/week. Someone manually matches each PDF line item to a purchase order. Errors lead to overpayments and disputes.

🚚

Delivery Blindspot

Customers call to ask "where is my order?" Nobody knows until someone logs into the courier portal and checks manually.

📋

Paper Pick Lists

Warehouse staff get printed pick lists every morning. A last-minute order? Reprint the whole thing. Wrong zone assignment = wasted 20 min walks.

📊

No Daily Insight

Managers have no real-time picture of what shipped, what's delayed, what's low on stock — until the weekly Excel report arrives Friday night.

Agent Walkthrough

A Day in the Life of SwiftStock's Agent

☀️

7:00 AM — Morning Brief

Agent queries ERP + shipping API → sends Slack summary: "23 orders pending, 4 delayed shipments, 3 SKUs below reorder point, $18K in unmatched invoices."

📧

9:15 AM — Order Arrives via Email

Hermes reads email → extracts: client, 12 SKUs, quantities, delivery address → checks stock → reserves items → creates ERP order → pushes zone-optimised pick list to staff's mobile app → replies to client with confirmation & ETA.

📦

11:30 AM — Stock Drops Below Threshold

After 3 orders for "Box-500ml", stock hits 40 units (reorder point: 50). Agent auto-generates a purchase order → sends to approved supplier via email → logs PO in ERP → sets a 3-day follow-up reminder.

🧾

2:00 PM — Supplier Invoice Received

PDF invoice arrives. Hermes extracts 34 line items → matches each to open PO → finds one discrepancy ($240 overcharge on SKU-882) → flags to accounts team with exact diff → approves the rest for payment automatically.

🚚

4:45 PM — Delivery Delay Detected

Agent polls FedEx API → shipment #8821 stuck in transit 2 days. Automatically notifies the client via email with apology + revised ETA → escalates to ops team on Slack → logs incident in CRM.

🌙

6:00 PM — Evening Report

Agent compiles: 47 orders processed, 2 exceptions, 1 PO raised, $0 overcharge paid, 3 delayed shipments handled. Report emailed to management. Agent sleeps — ready for 7 AM tomorrow.

Under the Hood

How Hermes Actually Does It

Three function calls — one natural-language trigger.

# Step 1 — Hermes reads the email and extracts structure tools = [ { "name": "check_inventory", "desc": "Query ERP stock levels for a list of SKUs" }, { "name": "create_order", "desc": "Create a new sales order and return order_id" }, { "name": "send_pick_list", "desc": "Push a zone-optimised pick list to staff app" }, { "name": "raise_purchase_order", "desc": "Create & email a PO to the approved supplier" }, { "name": "notify_client", "desc": "Send confirmation/delay email to client" }, ] # Step 2 — Hermes reasons and chains the right calls # Input: raw email text → Hermes decides the sequence tool_call: check_inventory({ "skus": ["BOX-500", "PAL-L", "WRAP-CL"] }) # ↳ returns: { "BOX-500": 340, "PAL-L": 12, "WRAP-CL": 890 } # ↳ Hermes sees PAL-L = 12 (below reorder 50) → flags it tool_call: create_order({ "client_id": "C-204", "items": [...], "delivery": "2026-05-20" }) # ↳ returns: { "order_id": "ORD-9981", "status": "confirmed" } tool_call: send_pick_list({ "order_id": "ORD-9981", "optimise_by": "zone" }) tool_call: raise_purchase_order({ "sku": "PAL-L", "qty": 200, "supplier": "SUP-07" }) tool_call: notify_client({ "client_id": "C-204", "message": "Order ORD-9981 confirmed, ETA May 20" }) # All 5 calls triggered by one email — zero human keystrokes
